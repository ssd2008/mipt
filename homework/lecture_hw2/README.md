# ФизКат. Домашнее задание №2

## Сборка и запуск

Из каталога `homework/lecture_hw2` в репозитории выполните:

```sh
c++ -std=c++17 -Wall -Wextra -Wpedantic main.cpp -o /tmp/fizkat
/tmp/fizkat
```

По одной команде на строку. Инвентарный номер `id` и имя `name` задаются без пробелов. Номера уникальны и чувствительны к регистру.

| Команда | Что делает |
| --- | --- |
| `add scooter id name energy score` | Принимает электросамокат после техосмотра |
| `add bike id name score` | Принимает обычный велосипед после техосмотра |
| `add ebike id name energy score` | Принимает электровелосипед после техосмотра |
| `add helmet id name` | Ставит шлем на баланс |
| `add dock id name energy` | Ставит док-станцию на баланс |
| `add trailer id name` | Ставит велоприцеп на баланс как вещь |
| `list` | Печатает все позиции как `id name`, по возрастанию `id` |
| `novice` | Печатает прокатный транспорт с оценкой от 6, по возрастанию `id` |
| `energy` | Печатает суточное энергопотребление с одним знаком после точки |
| `count` | Печатает число позиций на балансе |
| `count_novice` | Печатает число позиций, подходящих новичкам |
| `focus id` | Выставляет существующую позицию на витрину |
| `show_focus` | Печатает `id name` или `expired`, если витрина пуста |
| `remove id` | Снимает позицию с баланса |
| `quit` | Завершает программу |

`energy` во входных данных задаётся в кВт·ч/сутки конечным неотрицательным числом. `score` задаётся целым числом от 1 до 10.

## Иерархия и операторы

В [Inventory.hpp](Inventory.hpp) стрелки идут от базиса к наследнику:

```text
InventoryItem → NamedItem → Transport → Scooter
                                     → Bike → ElectricBike
                          → Helmet
                          → Dock
                          → Trailer

EnergyConsumer → Scooter, ElectricBike, Dock
```

У `Scooter`, `ElectricBike` и `Dock` множественное наследование. Их реализации `dailyEnergy()` переопределяют метод обоих базисов. В отчётах виртуальные методы вызываются через `InventoryItem`. Оператор `<<` вызывает виртуальный `describe()`, а оператор `<` сравнивает позиции по номеру при сортировке.

## Владение и исключения

В [main.cpp](main.cpp) новая позиция создаётся под `unique_ptr<InventoryItem>`. В [Fleet.hpp](Fleet.hpp) парк сначала вызывает виртуальный `inspect()` и проверяет уникальность номера. После проверок владение переходит к `shared_ptr<InventoryItem>` в векторе. При исключении временный указатель уничтожает кандидата, а вектор сохраняет своё состояние.

Витрина хранит `weak_ptr`. Метод `lock()` (англ. *lock*, «закрепить») на время печати получает `shared_ptr`, если позиция ещё жива. После удаления позиции витрина печатает `expired`, даже если тот же номер присвоили новому объекту.

- `InspectionRejected` наследуется от `FleetError` и возникает, если в имени транспорта есть `broken` в любом регистре.
- `ArgumentError` наследуется от `FleetError` и возникает при ошибке разбора, выходе аргумента за допустимые границы, повторном номере или обращении к неизвестному номеру.
- `main` печатает `error: ...` и переходит к следующей команде.

## Шаблон и творческая часть

В [Fleet.hpp](Fleet.hpp) шаблонная функция `sumReport` использует `ReportTotal<Value>` с оператором `+=`. Один обход используется в отчёте `energy` с накопителем `double` и в `count_novice` с накопителем `std::size_t`. В первом случае вклад позиции равен её суточному расходу, во втором равен 1 для транспорта, подходящего новичкам, и 0 для остальных позиций.

Добавлены класс `Trailer` с командой `add trailer` и отчёт `count_novice`.
